## Trace evidence and acceptance gates

[Chrome DevTools Tracing](https://chromedevtools.github.io/devtools-protocol/tot/Tracing/) provides trace collection and category discovery, not a GPU-kernel guarantee. [Chromium WebGPU decoder source](https://chromium.googlesource.com/chromium/src/+/main/gpu/command_buffer/service/webgpu_decoder_impl.cc) records Dawn command processing around CPU wire-server calls. The saved snapshot provides exact locators; no duration of those scopes will be labeled GPU execution. [Dawn platform source](https://chromium.googlesource.com/chromium/src/+/main/gpu/command_buffer/service/dawn_platform.cc) also contains CPU worker task tracing.

[Perfetto GPU documentation](https://perfetto.dev/docs/data-sources/gpu) describes driver GPU activity producers, which can have vendor-specific data-source names. Availability must be discovered on the actual phone. [Official GPU event schema](https://raw.githubusercontent.com/google/perfetto/main/protos/perfetto/trace/gpu/gpu_render_stage_event.proto) has optional durations and correlation metadata. A schema capability does not establish driver support, complete compute coverage, per-dispatch granularity or WGSL operator labels. A validated stage timeline can remain coarser than a kernel table.

Future acceptance requires: producer and installed backend identity; GPU-origin timestamps with documented time units/clock conversion; intact capture/coverage; actual context and submission identity; explicit shader/pipeline mapping for operator attribution. CPU flow arrows and chronological proximity alone fail this gate. Trace overhead and hardware-scope contamination must be reported. No phase labels may be inferred just from shader repetition patterns.

Existing PROFILE003/TIMING002 evidence remains authoritative: overlap reproduced independently, serial waiting changes execution conditions, platform cause UNKNOWN. This review neither reorders/truncates intervals nor repeats diagnostics. Model pass sums are not exclusive end-to-end GPU time; mixed multi-dispatch passes are not split among operators. Union remains only observed-interval union, not physical GPU busy time.
